# Telegram Auto Poster

Schedules marketing posts to Telegram groups **through your own Telegram user account (MTProto)**. It does not use the Telegram Bot API and
never needs a bot in your groups. You run it yourself (web service + background worker + PostgreSQL, packaged for Docker Compose).

**Start here: [docs/INSTALLATION_GUIDE.md](docs/INSTALLATION_GUIDE.md)** (installation, settings, database, deployment, backups,
troubleshooting, Telegram limits, honest delivery risks).

## Quick start (details in the installation guide)

```
python scripts/generate_keys.py --init-env      # creates .env with fresh secrets (back it up!)
# edit .env: APP_URL=https://your.address , APP_ENV=production , LICENSE_FILE_CONTENT=<license line from the seller>
docker compose up -d --build                    # database + migrations + web + worker
```

Open `APP_URL`, create the administrator with your `SETUP_TOKEN`, connect your Telegram account, refresh groups, write a post, schedule it.

## The encryption key

`SESSION_ENCRYPTION_KEY` protects the stored Telegram sessions. **Back it up**: without it, stored sessions cannot be decrypted. It may be a
Fernet key (what `generate_keys.py` prints) or any random secret of at least 32 characters, for example one generated by a hosting platform;
the latter is converted with HKDF-SHA256, deterministically. Never share it and never commit `.env`.

## Security summary

Passwords scrypt-hashed; server-side sessions with `HttpOnly`/`SameSite` cookies (`Secure` over https); CSRF tokens and Origin checks on every change;
login rate limiting; strict Content-Security-Policy; Telegram sessions and API credentials encrypted at rest (Fernet, bound to user and account);
secrets masked in logs; images validated by content; every record scoped by user and Telegram account; **production refuses to offer the
first-run page without a `SETUP_TOKEN`** and always enforces the license. Offline licensing does not protect against someone who edits the
source code; see `docs/LICENSING.md` for the honest limits.

## Layout

`app/` application (`web`, `workers`, `scheduler`, `telegram`, `posts`, `licensing`, `auth`, `security`, `db`), `migrations/` PostgreSQL schema
(forward-only, checksummed, advisory-locked), `Dockerfile`, `docker-compose.yml`, `docker-compose.https.yml` (optional Caddy HTTPS),
`.env.example`, `scripts/generate_keys.py`.

## Tests (seller repository)

`python -m unittest discover -s tests -t .` runs the suite offline (SQLite + fake Telegram network). PostgreSQL-specific tests need a database:
set `TEST_DATABASE_URL` (it **drops and recreates** the public schema of that database). The GitHub CI runs everything against real PostgreSQL.
No test sends real Telegram messages.
